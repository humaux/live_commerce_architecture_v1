# 商家金流与物流设置 v1

2026-09-20，`DESIGN_REQUIREMENT`；本文件不是已实现的 API、数据库迁移或供应商验收。
用户补充的两张现平台截图确认了配置体验：按供应商/服务列卡片，可编辑、启用和
控制买家展示。截图上的“自主模式”是原平台标签，不能推断为手工模式或已通过 API。

## 1. 范围与复用

- 平台维护适配器能力目录，商家连接自己的账户并按店铺配置方法；平台订阅费与
  商家商品货款分开。不强迫全部商家使用同一家物流/PSP或平台代收账户。
- 复用现有 integration binding、版本化 pricing policy、T06 外部操作/幂等台账、
  订单/支付/包裹边界。不新增第二个计价器、订单引擎或供应商微服务。
- 截图作为接入候选清单：PAYUNi（ATM/信用卡/分期/超商代码）、LINE Pay、
  绿界金流及物流、黑猫、新竹、7-ELEVEN/全家选店。目录可先展示“待接入”，
  但未完成适配/商家授权/对应环境验收的能力不能亮成“已连接”。
- 保留商家自行发货/外部运单录入与手动转帐等独立方式，但不得用它们冒充
  自动建单、API收款、自动对账或退款。新增供应商逐项接入，不一次承诺全支持。

## 2. 配置状态与运行时可用性分别管理

|层|含义|约束|
|---|---|---|
|账户连接|供应商、商家账户、环境、凭据版本、可用能力、检查时间及错误|仅服务器持有密钥；sandbox 与 live 不能混用；按租户/店铺授权|
|方法启用|商家是否接单、服务模式、地区/币种/金额/温层限制、费用政策版本|保存配置不等于外部已开通；不满足依赖时拒绝启用 API 方法并说明缺项|
|买家展示|展示名称、简繁英文案、排序、可见性|可见不等于可用；买家提交时服务端再次核验，不信任传入的方法 ID|
|运行时可用性|当前订单、账户环境、配置版本、适配器能力和供应商状态的服务端检查结果|不是第四个手动开关；缺少证据返回不可用及原因，不能因为配置已保存就推断可收款／可发货|

API 方法可用于新交易，须同时满足：适配器该能力已验收、商家账户与环境匹配、
方法已启用且允许该入口、当前订单满足币种/地区等限制。人工方式使用其独立
权限/适用规则，不需要虚构 provider 连接。这里的版本是持久化配置版本，不是
前端临时开关。配置变化须 CAS、防跨店、审计并令旧报价在提交时重验。

## 3. 物流与门市

- `PickupDestinationRevision` 只保存经过可追溯目录/核对的门市快照：品牌、
  原始字符串代码及 namespace、名称、地址、来源/版本/时间、买家和购物车归属。
  保留 `017888` 前导零。公共店号与某承运商服务代码不能猜测转换。
- `FulfillmentServiceRevision` 独立描述店铺启用的方式，首轮区分 `MANUAL` 与
  `API`，绑定价格政策与适用限制；具体 DDL 随 checkout 聚合冻结。
- MANUAL：买家无需选择具体承运商；商家可先按店取服务接受订单，再安排承运商。
  订单明确“待商家安排”，不创建物流 API 任务。发货时登记实际承运商/服务/单号，
  核对该路线店码，导出或回填均审计。无法核验不能伪称 API 已验证。
- API：复用该商家已连接账户，按适配器能力选店、建单、面单、查件和对账。
  不把台湾国内/台湾出口接口当境外入台线路；失败/UNKNOWN 不自动改成人工成功。
- 轨迹查询独立于建单，可接商家外部运单；未知时展示“暂无轨迹”，不能编造到店。
  COD 默认关闭，须另有有效代收能力证据，不能由超商取货开关推导。

## 4. 支付与停用

- 同一商家可连接多个 PSP，按支付方式启用；每个 payment attempt 固定其账户、
  环境、方法、金额、币种、订单和幂等标识，不能因后来修改默认方式而改收款账户。
- “超商代码缴费”“超商取货”“取货付款”是三种不同事实/能力，不互相解锁。
  手动转帐的买家上传凭证不等于付款成功；由获授权商家核对并留审计。
- 回调除验签，还需核对账户/订单/金额/币种，处理重复、乱序和超时；前端成功页
  不记已收款。退款沿原支付事实和金额上限，不盲切其他 PSP 重试。
- 隐藏/停用只影响对应方法的新选择/新操作，不能停止客户直播、删除绑定历史、
  遗失在途支付/物流回调或触发退款。解绑/凭据撤销先提示在途影响；保留必要的
  查询/对账路径。运行时不得把明文密钥返给浏览器或写入日志。

## 5. 验收 gate（均 NOT_RUN_PRODUCT）

|Gate|必须证明|
|---|---|
|MS01 隔离|两商家连接同类供应商不同账户；配置/凭据/回调/退款/运单互不可见、不可串用|
|MS02 启用与展示|保存后刷新读回；隐藏/禁用/未连接方法不能被买家伪造 ID 选用；三语与手机可操作|
|MS03 人工店取|承运商/单号为空仍可按已启用服务选店下单；记录待安排，零自动建单/虚假可达/COD声明|
|MS04 接口店取|错误环境/服务/店码映射拒绝；已通过目录回填不冒充实际运输验收|
|MS05 费用与版本|换方式/店址或管理员改规则后重新计价；客户端金额无效；旧 revision 不静默接受|
|MS06 收款|sandbox 成功/失败/超时、错账户/金额/币种、重复乱序回调及退款限额；live 另行批准|
|MS07 停用竞态|选择后被停用则提交拒绝；已存在 payment attempt/包裹继续可查询对账，不自动取消/重发|
|MS08 外部运单|不同承运商同单号不串单；重复导入幂等；部分失败可重试，未知轨迹明确标示|

对应商家 B05/B10、买家 C04/C05、T05/T11/T13/T18/T20 和 G01/G03/G04/G05/G08/G11。
无供应商账户时继续 mock/真实本地数据库测试，不能将其标为 sandbox/live。
升级信号：某服务商成为真实首发需求时，按正式文档冻结该适配器、商户授权与实测矩阵；
不是要求所有租户或全站先确定一家承运商。

独立文档窄复核：`t06_operation_service`，`PASS_BOUNDED`，P0=0/P1=0；
Humaux `f31f5676-97cb-41e5-be58-aff580bf19f3`。仅证明本设计与用户需求及边界一致，
不提升上述任何产品/供应商 gate 状态。
