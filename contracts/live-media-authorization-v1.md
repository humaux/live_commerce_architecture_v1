# T08 prepared media authorization registry — LMA01–05

Status: **FROZEN_FOR_MOCK_REGISTRY_IMPLEMENTATION**. Independent preflight closed
schema-USAGE and global lock-order P1s; parsed JSONB/replay semantics clarified.
No open P0/P1 in the bounded contract. This is the database custody/registration increment of
the durable media controller, not a runnable broadcaster. It adds no HTTP route,
media attempt, operation, queue, worker, provider call or merchant permission.
No LIVE registration is accepted. Existing LKP/LKM acceptance stays separate.

## Why this increment exists

The controller needs an immutable, tenant-bound encrypted destination set and a
revocation history that generic merchant bindings cannot mint. Reuse PostgreSQL
constraints and fixed SECURITY DEFINER functions; no framework, credential copy
in merchant JSON, new Go dependency or competing ledger. This increment only
persists prepared authority; later Start planning must recheck its eligibility,
exact draft version and current merchant permission under its own transaction.
Successful registration is not authority to start a provider resource.

## SQL surface (migration 0034, no edits to historical migrations)

Create NOLOGIN/NOSUPERUSER/NOBYPASSRLS/NOCREATEDB/NOCREATEROLE/NOREPLICATION roles
`commerce_media_registrar` and `commerce_media_writer`. No existing application
role or login is granted either role. The writer is private and owns only the
two fixed functions. Grant `USAGE ON SCHEMA live` to registrar and writer;
the registrar gets only the two function EXECUTE privileges within that schema,
never table/ciphertext SELECT or direct INSERT/UPDATE/DELETE. The writer also
needs USAGE on control/integration for its qualified dependency accesses.
All new tables enable and FORCE RLS.
Writer policies/grants permit only the operations needed below, not DELETE.
Fixed search_path `pg_catalog`; all non-catalog relations/functions qualified.
Explicitly REVOKE function EXECUTE FROM PUBLIC after creation.

### Register

`live.register_prepared_media(p_spec jsonb, p_nonce bytea, p_ciphertext bytea)
RETURNS uuid`, SECURITY DEFINER owned by `commerce_media_writer`.

`p_spec` must be a closed JSON object with exactly these non-null fields. Reject
unknown fields and wrong JSON scalar types (do not coerce a string to an integer
or a numeric value to text). Canonical JSONB size `octet_length(p_spec::text)`
<=16 KiB. SQL receives parsed JSONB: original whitespace, duplicate raw keys and
number spellings have already been normalized; raw parser validation belongs to
the future trusted registrar caller and is not claimed by this SQL gate.
Required JSON strings:

- `id`, `tenant_id`, `store_id`, `session_id`, `attempt_id`, `media_binding_id`:
  canonical lowercase nonzero UUIDs; ids are generated by trusted registrar code,
  not by a merchant request. `attempt_id` is unique across authorizations.
- `environment`: exactly `MOCK`. No flag or evidence string admits LIVE.
- `project_id`: `[A-Za-z0-9_-]{1,80}`; `endpoint_identity`: canonical HTTPS
  origin of one lowercase DNS label before `.livekit.cloud`, matching the LKP
  grammar; no slash, userinfo, port, path, query or fragment.
- `aspect_ratio`: `16:9` or `9:16`.
- `evidence_type`: exactly `MOCK_FIXTURE`; `evidence_hash`: 64 lowercase hex;
  `evidence_issuer`: `[A-Za-z0-9_-]{1,64}`. These record provenance, not proof of
  real Meta eligibility. Registered database login is also stamped by the DB.
- `start_before`: UTC RFC3339 string with literal Z; finite timestamp must be
  strictly after the final database clock and <=24 hours after that clock.
- `budget_currency`: three uppercase ASCII letters. This is a declared cap,
  not a billing guarantee or a conversion estimate.
- `key_id`: `[A-Za-z0-9_-]{1,64}`.

Required positive JSON numbers with integral values (no string coercion;
JSONB normalizes equivalent exponent notation, which is not a distinct input):
`session_version`, `credential_version`, `media_binding_version`,
`material_version` (signed bigint range); `max_duration_seconds` 1..14400;
`budget_minor` 1..1000000000.

`destinations` is a JSON array of one or two closed objects, each containing
exactly `binding_id` (canonical nonzero UUID string), `binding_version`
(positive bigint JSON integer), `provider` (`facebook` or `instagram` string),
`external_asset_id` (trimmed string 1..200 characters without controls).
Array position becomes ordinal 1 or 2. Repeated binding IDs or repeated
provider/asset pairs are rejected, not silently deduplicated. The media binding
must differ from all destination bindings. No URLs or tokens enter this JSON.

Nonce length exactly 12 bytes; ciphertext length 16..16400 bytes, matching LKM.
SQL checks envelope shape, not cryptographic validity. LKM sealing/opening and
later final dispatch eligibility remain distinct gates; do not claim that SQL
can authenticate ciphertext or that an evidence hash proves ownership.

Registration validates current enabled media binding provider=`livekit`, asset=
project ID, exact version and scope; every destination binding matches its
declared provider/asset/version and scope and is enabled. Tenant/store active;
session and program exist in the same scope; program is DRAFT; session version
and program aspect exactly match. No implicit live:* or integration:* grants.

Lock all referenced bindings in sorted UUID order, then tenant/store, session
and program, then any existing authorization row. Read locators without claiming
authority and revalidate after all waits. Grant the private writer only the
SELECT/row-lock privileges required on existing tables, with private RLS
policies where needed. Do not broaden existing runtime/worker policies.

Insert the header and ordered children atomically; failures leave neither.
`id` is the idempotency key. Exact means equal parsed typed fields, equal ordered
destinations and byte-identical nonce/ciphertext, not identical raw JSON syntax.
An exact replay returns the same ID only while
current eligibility and deadline still pass and the authorization is unrevoked.
Changed spec, scope, nonce or ciphertext under the same ID fails; never overwrite
or revive it. Concurrent identical registration returns one header/child set.
Recheck time and revoked status after a conflicting insert/row-lock wait before
returning. A transaction rollback removes the whole new registration.

### Revoke

`live.revoke_prepared_media(p_tenant uuid, p_store uuid, p_authorization uuid,
p_reason text) RETURNS void`, same owner and registrar-only EXECUTE.

Require nonzero IDs, exact existing scope and reason matching
`[A-Za-z0-9_.:-]{1,80}`. Append one immutable revocation for the authorization,
recording DB time and `session_user` as the trusted login. Exact repeated reason
is a no-op; a different reason conflicts rather than rewrites history. Scope
mismatch or missing authorization fails. Revocation remains possible after
expiry, binding disable/version change or store disable: it reduces authority.
No un-revoke/delete path. It does not call Stop or impersonate a merchant.

### Persisted schema and diagnostics

`live.prepared_media_authorizations`: explicitly typed columns corresponding
to the scalar spec fields (hash as bytea), plus nonce/ciphertext, `registered_by`
text and `created_at` timestamptz. Primary key id; unique attempt_id; unique
(tenant_id,store_id,id); composite scope FKs to live.sessions and
integration.bindings. Required types/checks above also live on the table where
possible. No JSON authority blob in lieu of typed ownership/constraints.

`live.media_authorization_destinations`: authorization_id, tenant_id, store_id,
ordinal smallint 1..2, binding_id, binding_version bigint, provider,
external_asset_id. PK(authorization_id,ordinal), unique(authorization_id,
binding_id), unique(authorization_id,provider,external_asset_id); scoped
authorization and binding FKs. No direct mutation or delete grants.

`live.media_authorization_revocations`: authorization_id primary key, tenant_id,
store_id, reason_code, revoked_by text, revoked_at; scoped authorization FK.
No customer PII, plaintext stream URLs, API credentials or raw provider errors.

For well-formed JSONB arguments, all function validation/conflict/scope failures
raise SQLSTATE 22023 and a static
`media authorization unavailable` message, with no attacker text/detail/hint.
ACL denials remain native 42501. A malformed raw JSON value rejected by PostgreSQL
before function entry is outside this function's redaction boundary. Do not
swallow unexpected DB/infrastructure
failures as success. Missing/null/oversized input must be rejected before any
write. UUID/number/date parsing failures must not echo the offending value.
