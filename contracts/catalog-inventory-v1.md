# T04 v1 — catalog, price and physical inventory

Status: CONTRACT_FROZEN; implementation/tests must independently prove it. Owner: integrator. No customer production writes. Payment/checkout/fulfillment gates remain NOT_RUN until their own implementation.

## Boundary and invariants

All Go domain functions take `(context.Context, pgx.Tx, platform.Scope, ...)`; callers resolve merchant session + fixed permission through `platform.WithScope`. No pool, HTTP headers, client tenant ID or provider calls in domains. Every returned error must abort the owning transaction. Public/buyer checkout requires its separate trusted scope contract, not these merchant routes.

Use UUID strings generated by PostgreSQL; all relations carry `(tenant_id,store_id)`. FORCE RLS protects every table. Products/SKUs archive, never hard delete. Name <=120, description <=8000, SKU code 1..64 `[A-Za-z0-9_.-]`, currency equals store currency. Amounts are `int64` minor units in [0,1e12]; quantities <=1e9; checked multiplication and sums. Price history is append-only. Version starts 1 and optimistic updates require exact expected version. Weight grams and size millimetres are integers. Customs candidate and confirmed HS are separate; only a deliberate merchant-confirm operation may set confirmation actor/time (not part of T04 v1).

Inventory balance key `(tenant_id,store_id,warehouse_id,sku_id)`: `on_hand,reserved,allocated,unavailable,version`; all nonnegative, sum of unavailable/reserved/allocated <= on_hand. ATP is their difference, not a separate mutable column. Only INSERT into append-only `inventory.ledger` may change balances (DB trigger; runtime has no direct balance write grant). Each ledger row carries four deltas, kind, command operation/key, actor, reservation ID if relevant, and resulting balance version. Reserve/release kind deltas are constrained. Balance, reservation lines, command response, audit commit/rollback together.

Commands: operation + idempotency key unique per tenant/store; key 8..128 `[A-Za-z0-9_.:-]`. Service canonicalizes validated inputs then SHA256 JSON. Transaction-level advisory lock on scoped operation/key serializes retries; completed JSON result only is persisted. Same key/hash replays exact response; changed hash returns `command.ErrConflict`. No pending placeholder or external calls under lock. Lock hash collisions only serialize unrelated commands, never alter key equality. Validation errors store nothing. Replay still requires current authorization.

`inventory.lock_balance(warehouse_id,sku_id)` is the sole privileged lock/read helper. It returns the scoped balance row with FOR UPDATE and exposes no write. Ordinary runtime cannot run SELECT FOR UPDATE directly on balances because it intentionally has no UPDATE grant. The function owner is non-login and API pool startup rejects ability to SET this schema-owning role.

Reserve merges duplicate warehouse/SKU lines, verifies sum <=1e9, sorts `(warehouse_id,sku_id)` and locks balances in that order. All lines succeed or whole transaction fails. Product/SKU and warehouse must be active. Store header/version checks happen before balance locks; catalog readers lock product then SKU consistently against concurrent archive. Reserve TTL is server-created 15 minutes, never a client absolute expiry. T04 exposes domain Reserve for later BeginCheckout POST, **not** GET/comment or an unprotected public route.

Reservation states: HELD, PAYMENT_PENDING, COMMITTED, RELEASED, EXPIRED. This slice writes HELD and HELD→RELEASED/EXPIRED only; it must refuse pending/committed release. Release locks header first then sorted balances, retains immutable lines, appends release ledger. Expiry requires DB time >= expires_at. Idempotent release of terminal RELEASED/EXPIRED returns unchanged reservation without duplicate deltas. Payment owns pending/committed later; no old-TTL release and no refund→restock shortcut.

## Exact Go API for parallel implementation/tests

`internal/command`: exported `ErrInvalid`, `ErrConflict`, `ErrNotFound`, `ErrInsufficient`; `Run(ctx,tx,scope,operation,key string,request any,result any,fn func() error) error`. `result` is a pointer; Run validates key, computes hash, replays JSON into result, or executes fn and persists result. `CheckMoney(unit,quantity int64) (int64,error)` bound 1e12 total; `ValidID(string) bool`; `Audit(ctx,tx,scope,action string) error` inserts ops.audit_events without payload secrets.

`internal/catalog` types (all exported DTO fields use snake_case JSON):
- `Product{ID,Name,Description,Status string; Version int64}`
- `ProductInput{Name,Description string; ExpectedVersion int64}`
- `SKU{ID,ProductID,Code,Status,Currency string; PriceMinor,Version,WeightGrams,LengthMM,WidthMM,HeightMM int64; OriginCountry,CustomsName,HSCandidate string}`
- `SKUInput{ProductID,Code string; PriceMinor,WeightGrams,LengthMM,WidthMM,HeightMM int64; OriginCountry,CustomsName,HSCandidate string; ExpectedVersion int64}`
- `PriceInput{PriceMinor,ExpectedVersion int64}`
- `CreateProduct(ctx,tx,scope,key string,in ProductInput)(Product,error)`
- `UpdateProduct(ctx,tx,scope,key,id string,in ProductInput)(Product,error)`
- `ArchiveProduct(ctx,tx,scope,key,id string,expectedVersion int64)(Product,error)`
- `ListProducts(ctx,tx,scope)([]Product,error)` maximum100 stable id order (empty [] not null).
- `CreateSKU(ctx,tx,scope,key string,in SKUInput)(SKU,error)`
- `UpdateSKU(ctx,tx,scope,key,id string,in SKUInput)(SKU,error)` metadata/code only; price in request must equal current or use SetSKUPrice. ProductID immutable.
- `SetSKUPrice(ctx,tx,scope,key,id string,in PriceInput)(SKU,error)` updates SKU price/version and appends price_history; zero is legal.
- `ArchiveSKU(ctx,tx,scope,key,id string,expectedVersion int64)(SKU,error)`
- `ListSKUs(ctx,tx,scope,productID string)([]SKU,error)` maximum100, rejects foreign/missing product.

`internal/inventory`:
- `Warehouse{ID,Name string}`; `CreateWarehouse(ctx,tx,scope,key,name string)(Warehouse,error)`; `ListWarehouses(ctx,tx,scope)([]Warehouse,error)` limit100.
- `Balance{WarehouseID,SKUID string; OnHand,Reserved,Allocated,Unavailable,Version,Available int64}`.
- `Adjustment{WarehouseID,SKUID string; Delta,ExpectedVersion int64; Reason string}`. ExpectedVersion0 means only a missing balance; adjustments require nonzero delta within ±1e9 and reason1..240. Lock existing balance with expected version; first concurrent creation serialized by `(scope,warehouse,sku)` advisory lock before balance access. No direct balance writes.
- `AdjustOnHand(ctx,tx,scope,key string,in Adjustment)(Balance,error)` and `ListBalances(ctx,tx,scope)([]Balance,error)` limit100.
- `Line{WarehouseID,SKUID string; Quantity int64}`; `Reservation{ID,State string; ExpiresAt time.Time; Lines []Line}`.
- `Reserve(ctx,tx,scope,key string,lines []Line)(Reservation,error)` 1..50 raw lines; missing/foreign/archived rows fail; inadequate ATP ErrInsufficient. Errors roll back entire transaction.
- `ReleaseReservation(ctx,tx,scope,key,id string,expire bool)(Reservation,error)`. Fixed operation separates release/expiry; expire on unexpired HELD ErrConflict; pending/committed ErrConflict. Only authorized internal caller, no generic GET mutation.

## Tables and audit operations

Tables/columns are defined exactly in `migrations/0002_catalog_inventory.sql`; money/status/RLS/FK/check constraints are authoritative. Use explicit columns, parameterized SQL. Audit actions: `catalog.product.created/updated/archived`, `catalog.sku.created/updated/archived/price_changed`, `inventory.warehouse.created`, `inventory.adjusted`, `inventory.reserved`, `inventory.released/expired`. Audit once on original successful command, not replay.

## Acceptance gates (REAL_PG + independent review)

Cross-tenant/store reads/writes and scoped FKs; ordinary runtime direct balance write denied; ledger/history update/delete denied; same-key simultaneous replay one result and one audit; changed input conflict; optimistic stale edit; price history and money overflow; inventory1 two independent connections only one reserve; multi-SKU reverse order no deadlock/partial success; duplicate lines canonicalize; terminal release exactly once; pending/committed cannot release; early expiry rejects; errors/cancel roll back result+balance+ledger+audit; archived product/SKU rejects new reservation while historical rows remain. Tests include HTTP only when route contract lands; model tests do not substitute real PG.
