## Root cause and bounded product fix

In `tests/storefront/home-cod-buyer.mjs:202–262` (`COD-255 gap-up`, `gap-down`, `gap-zero`), the buyer requests a quote while `/api/buyer/checkout-options` is held (`gap: true`). Because `paymentMode` defaults to `"card"` before the buyer checks `cash_on_delivery` at line 262, `selected` in `OrderFlow.tsx:229` evaluates to `"card"` during the initial options load. While `checkout-options` is held, the merchant updates the COD surcharge (`signal(step("change"))`). When `checkout-options` is released, `found.cod_surcharge_minor` carries the new fee (`6000`), which disagrees with `currentQuote.cod_due_minor` (`2500 + 5000 = 7500`).

In FIX2 (`f35a8b363`), `OrderFlow.tsx:233–234` changed `const latest = await refreshCodQuote(context, currentQuote, found)` to only run when `optionRefresh || selected === "cash_on_delivery"`. As a result, when `selected === "card"`, `OrderFlow` skipped `refreshCodQuote`, never requested `GET /api/buyer/quotes/{id}`, and excluded `"cash_on_delivery"` from `paymentChoices` because `codQuoteMatches(currentQuote, found)` was false.

The fix in `apps/storefront/components/OrderFlow.tsx:231–241` always attempts `await refreshCodQuote(context, currentQuote, found)` (which is a no-op when COD is not offered or already matches `codQuoteMatches`). If `refreshCodQuote` throws:
- When `optionRefresh || selected === "cash_on_delivery" || !(reason instanceof BuyerClientError && reason.status === undefined)` (including COD-only shops where `modes[0] === "cash_on_delivery"`, explicit COD selection, fee-refusal recovery, or any HTTP/transport error), the error is rethrown to fail closed (`setNotice("failed")`), preserving all `COD-255` `failed` (`503`) and `RVFIX #273` invariants.
- When `selected !== "cash_on_delivery"` and `!optionRefresh` and `reason` is the validation mismatch from a 200 quote response (`reason instanceof BuyerClientError && reason.status === undefined`, e.g. the pinned card re-quote mock in `tests/storefront/checkout-v2.mjs:531–550` that modifies card total without updating `cod_due_minor`), `latest` stays `currentQuote`, `codQuoteMatches(latest, found)` filters out stale COD from `paymentChoices`, and card review remains enabled.
