- Risks:
  1. Per-shard time depends on how much faster one uncontended worker is than three contended ones (unmeasured; PLAN.md gives the range 11-18 min at N = 10). Retune `SWEEP_SHARDS` in `scripts/dev/ci-plan.mjs` after the first run.
  2. A full dispatch is 25 jobs; if the account's concurrent-job limit is below that, queue time is added and not in the estimate.
  3. Job-minutes rise about 75% (160 -> 280) for -75% wall.
  4. Admin route variants of one route may now run in different shards, each on a pristine store (before, later variants saw the earlier variant's clicks). Stronger isolation, but the observed state of variant 2/3 is not identical to the old run: a first sharded run may surface a defect that was masked, or lose a flaky `destructive-changed-state` from the old 3-worker fingerprint race.
  5. `output/ui-click-sweep/ledger.json` is tracked in git: a shard that dies before writing its ledger uploads the committed one, which has no `summary.shard`, so the aggregate reports it as "not a shard ledger" (fails closed).
  6. `go test -skip` of the catch-all is a 43 KB argument (limit 128 KB); `scripts/dev/shard-plan.mjs --check` fails if it ever nears that (`tests/ci/shard-plan.test.mjs`) or when more than 60 tests are unplanned (regenerate the plan).
  7. A dispatch of foundation groups WITHOUT the unit shard does not run `go vet ./...` (it runs once, in the unit shard / serial run).
  8. Playwright cache restore needs `/opt/ms-playwright` writable (a chown step makes it so); on failure the install falls back to a download.
  9. `.github/workflows/foundation.yml` (pull_request / push main) still runs the serial suite.
- NOT_RUN / BLOCKED: every GitHub run (sharded sweep, sharded visual lint, the 10 foundation groups, the aggregate job, the Playwright cache hit); actionlint (not installed); a real `go test -skip` run of the catch-all group on CI (semantics verified with a scratch Go module on go1.26.2, CI uses go1.27.1).
