## Risks

1. The docs-inert scan is lexical: a Go test that reads docs through a lone bare `"docs"` / `"contracts"` literal plus runtime data is not seen (lone words are too common as field names). Safety net: every push to r3/integration still runs all foundation shards. Upgrade path noted in `pr-modes.mjs` (`ponytail:`).
2. `IGNORED_READS` has one entry (`scripts/dev/contractdrift/git.go` `contracts/` prefix classifier); the real contract read is the plan job's drift step, which runs on every PR.
3. The `build` job is now on the critical path (~2.5 min + queue) and a single point: if it fails every leg is skipped and `required` is red (fail-closed).
4. Go build cache restore assumes identical runner image, toolchain (`GOTOOLCHAIN=go1.27.3`) and workspace path; any mismatch only causes cache misses (Go keys entries by content), never different results.
