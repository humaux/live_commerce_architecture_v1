# ci-speed plan: before / after (estimates, to be replaced by the integrator's measured runs)

Evidence class: DESIGN + local E3 for the pure parts (node tests, check-gates). Every "after" number below is an ESTIMATE: no GitHub run of this branch exists yet.

## Before (measured 2026-10-07, run 37576812361 for the sweep, 37576812655 for the foundation shards)

| Gate | Job wall | Where the time goes |
| --- | --- | --- |
| `--browser-click-sweep` | 53 min (47-67 over runs) = 292 s setup + 2903 s Go test | runner log: admin phase 2656 s at 3 workers, storefront walks 214 s, journeys 28 s |
| `--browser-visual-lint` | 14 min (14-35) | 3 workers |
| foundation `^TestL` / `^Test[B-K]` / `^Test(A\|[N-R])` / `^Test[S-Z]` / `^TestM` / unit | 22 / 17-20 / 12-18 / 15-16 / 15 / 6-7 min | tests are serial (sum of top-level durations = go test wall); sum over the 5 foundation shards = 4754 s (79 min); fixed cost per shard about 137 s (compile + PG + `go vet ./...`) |
| every job | about 75 s setup, `playwright install --with-deps` 47-53 s of it for browser modes | |

Critical path of a full run = the click sweep, 47-67 min.

## What changed

1. Click sweep and visual lint are partitioned (`LC_SWEEP_SHARD=i/N`, `tests/ui/sweep-shard-lib.mjs`), one slice per job, plus an `aggregate` job (`tests/ui/sweep-aggregate.mjs`).
2. Foundation: 10 balanced groups from measured seconds (`scripts/dev/shard-timing.json` -> `scripts/dev/shard-plan.json`, generated by `scripts/dev/shard-plan.mjs`) instead of 5 letter-range shards.
3. A `plan` job (`scripts/dev/ci-plan.mjs`) expands the dispatch `modes` into the matrix; `--browser-click-sweep` and `--browser-visual-lint` keep their names.
4. Playwright browsers cached per Playwright version; `go vet ./...` runs once per full run (unit shard) instead of once per foundation shard.

## Choice of N (the only knob that matters)

Measured worker-seconds of the sweep (3 workers, so contended): admin 7574 + storefront 3 x 214 + journeys 28 = **8244 s**. A shard runs ONE worker (no fingerprint race: own PG/store), which can only be faster per unit than the contended 3-worker time: between 1x and about 2x. Per-shard sweep time = 8244 / N / c, c in [1, 2]; fixed cost per shard job about 292 s - 35 s (Playwright cache) = 257 s.

| N | planned load spread (LPT on measured weights) | shard job, c = 2 | c = 1.4 | c = 1 |
| --- | --- | --- | --- | --- |
| 6 | 1428-1430 s | 15.7 min | 20.6 min | 27.2 min |
| 8 | 1070-1073 s | 12.9 min | 16.6 min | 21.5 min |
| **10** (chosen) | 855-862 s | **11.2 min** | **14.1 min** | **18.0 min** |
| 12 | 712-723 s | 10.0 min | 12.5 min | 15.7 min |

N = 10 is the smallest N that meets the 20 min target even at c = 1 (no speed-up from dropping the 2 extra workers; N = 8 misses it there). If the first measured shard is well under 12 min, N = 8 is enough; if over 15 min, raise to 12: change `SWEEP_SHARDS` in `scripts/dev/ci-plan.mjs` (nothing else; weights and the aggregate adapt). The weights file `tests/ui/click-sweep-weights.json` is built from the 25-route run; the 2 routes added since (`/settings/payments/card`, `/settings/settlements`) take a default weight until re-measured.

Visual lint: whole gate 14 min = about 265 s fixed + 540 s of audit at 3 workers. N = 4 (workers stay 3, it only reads): 135 s + 265 s = **6.7 min** (11.9 min in the 35 min outlier case).

Foundation: 4762 s of tests / 10 groups = about 470 s per group (LPT spread is flat: every group within one longest test of the others; the longest single test is `TestPasswordPA07Throttle` 274 s). Job = 75 s setup + about 70 s compile/PG (137 s measured minus about 65 s of `go vet`) + 470 s = **10.3 min**. The unit shard stays 6-7 min.

Cost: job-minutes go up. Before: 53 + 14 + 86 + 6.5 = 160. After: 10 x 14.1 + 4 x 6.7 + 10 x 10.3 + 6.5 + 1.5 = about 279 (+75%) for -75% wall. A full dispatch is 25 jobs (10 + 4 + 10 + unit) plus whatever other modes are listed; GitHub's concurrent-job limit of the plan is not in these numbers (queue time), so measure it alone.

## Not changed on purpose

- No assertion, threshold, coverage rule, known-defect rule, skip rule or test was removed or relaxed. Every admin registry route x 3 variants, every storefront route x 3 variants and journeys J1-J5 are still run; the aggregate fails on any gap (proof: `tests/ui/sweep-shard-lib.test.mjs`, red log `output/ci-speed/red-aggregate.log`).
- `.github/workflows/foundation.yml` (pull_request / push main) still runs the serial suite; reusing the shard plan there is a follow-up (it is not on the dispatch critical path measured here).
- Not done, possible later: build the two Next apps once and share them with the shards (saves job-minutes, not wall), Go build cache, caching the apt libraries of `playwright install --with-deps`.

Compare the longest shard with the table above to pick N.
