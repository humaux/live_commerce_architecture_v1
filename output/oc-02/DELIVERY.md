## Implementation
- `migrations/0201_recent_auth.sql`:
  - `identity.sessions.authenticated_at` is added nullable, then backfilled from the session's `session.issued` event (`-infinity` when the session has none), then set NOT NULL, then given DEFAULT `clock_timestamp()` (the default comes after the backfill).
  - `GRANT UPDATE (authenticated_at)` to commerce_identity_writer.
  - `issue_merchant_session` (0004) and `complete_email_challenge` (0070, which covers signup, login and reset) are re-created to write `authenticated_at = clock_timestamp()`.
  - `identity.require_recent_auth(p_hash, p_window)` raises PT403 `reauth_required` for a NULL, unknown, revoked or expired hash, an inactive principal, a disabled credential (PD12) or a stale `authenticated_at`. The window must be 1–60 minutes, otherwise PT400.
  - email_challenges: the purpose CHECK adds `reauth`; a new `session_hash` column with its CHECK; the shape CHECK requires principal, version and session hash on reauth rows; new open-challenge and PD5 budget indexes.
  - auth_events gains the actions `reauth.requested`, `reauth.verified` and `reauth.refused`.
  - New definers: `reauth_material`, `start_reauth_challenge` (supersedes the session's open reauth challenges), `complete_reauth_challenge` (session-bound, PD5 budget, 5 attempts, updates only that session).
  - OIDC: `login_flows.session_hash`, `start_oidc_reauth_flow` (session-authenticated), `consume_login_flow_with_session`, `complete_oidc_reauth` (principal match plus the 10-minute auth_time check in SQL).
  - The ordinary `consume_login_flow` no longer consumes re-auth flows.
  - All new definers: owner commerce_identity_writer, SECURITY DEFINER, `search_path=pg_catalog`, `REVOKE ALL FROM PUBLIC`, `GRANT EXECUTE TO commerce_identity`.
  - Re-runnable (IF [NOT] EXISTS / CREATE OR REPLACE).
- `internal/identity/reauth.go`:
  - `Passwords.StartReauth` and `CompleteReauth`.
  - `ErrReauthFailed` (403, never 401). A wrong password calls `record_password_failure`.
  - Throttle keys: principal and session hash.
  - `ReauthWindow` parses `COMMERCE_REAUTH_WINDOW_MINUTES`.
  - The code mail gets a reauth copy.
- `internal/identity/oidc_reauth.go`: `Service.StartOIDCReauth` and `Service.CompleteLogin`. A re-auth flow returns `{Reauth, AuthenticatedAt}` and no token, and is refused when auth_time is missing.
- `internal/identity/service.go`: `exchange` and `issue` are extracted. The existing `Complete` keeps its behaviour.
- `internal/oidclogin`: `ReauthAuthorizationURL` adds `prompt=login` and `max_age`; `Identity.AuthTime` is read from the `auth_time` claim, and a malformed value is an error.

## Risks / notes
- `complete_oidc_reauth` sets `authenticated_at = LEAST(auth_time, now)`, which is the moment the IdP actually proved the credential. This is stricter than `now`.
- The future-skew tolerance for auth_time is 1 minute.
- An OIDC-only principal calling StartReauth gets `ErrReauthFailed`; the UI must choose the OIDC path by itself.
- `Service.Complete` refuses re-auth flows (they are not consumed). OC-15 must switch the callback to `CompleteLogin`.
- `require_recent_auth` is EXECUTE for commerce_identity only. OC-03 must grant EXECUTE to the owners of the guarded definers.
- Known limit (§16): when mail is unavailable, password re-auth is blocked too.
- The merge commit fed149133 has no Co-Authored-By trailer. Adding it would need a rewrite, and force-push is forbidden.
