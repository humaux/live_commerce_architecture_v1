- Risks / findings for the reviewer:
  1. **SG01 "support reads orders -> 200" is NOT delivered.** The order list/detail definers (`identity.read_merchant_orders*`, 0027/0063/0110) and `identity.merchant_access_denied` (0063/0073, also customers/CVS/exports) fence with an inline `memberships.active` + `store_grants` join, not `resolve_access`; a support principal is refused there (and `merchantorders.validAuthorityInput` requires `Revision > 0`, answering 422). Serving order pages needs a conscious patch of those fences (+ the Go validators using `Revision > 0`: merchantorders/orders.go:289, notify/settings.go:50, customers/read.go:231, reporting/*.go). Pinned by test so a widening is deliberate. Needs integrator decision.
  2. Brief item 6 (403 body code `support_read_only`): the HTTP body stays the route's `forbidden`; `ErrSupportReadOnly` wraps `ErrForbidden` (handlers use `errors.Is`). A distinct body code is a per-handler follow-up.
  3. Support scope = `authz_revision -1` sentinel: any Go validator requiring `Revision > 0` refuses support (intended default-deny), SQL fences comparing a membership revision refuse it too.
  4. `support.used` is written inside the request transaction: a request that errors rolls its use row back. Throttled to one row per 15 min per principal+store (a race may write two).
  5. Granting to a principal that already has any `store_grants` row for that store is refused (PT409); granting on a suspended store/tenant is refused (PT409). Re-granting after expiry closes the old row with `revoked_at = expires_at`.
  6. `GRANT USAGE ON SCHEMA identity, ops TO commerce_platform_writer` and `USAGE ON SCHEMA identity TO commerce_platform_operator` were added; writer also got column-narrow SELECT on principals/memberships/store_grants, INSERT(tenant_id,principal_id,active) on memberships (placeholder, always active=false in the definer), INSERT on ops.audit_events limited by policy to the two support actions.
  7. Login of a principal without any active membership (password/OIDC) was not exercised end to end here (password `start_login_challenge` only uses membership for a mail-budget flag); `--operator` stays a self-asserted label like OPS-01B.
