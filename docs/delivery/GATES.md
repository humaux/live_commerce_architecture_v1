# Gates: what runs, what it proves, how to run it

Status: hand-kept, mechanically checked by `bash scripts/dev/check-gates.sh` (CI). The script fails when a
mode in the usage line of `scripts/dev/test-local.sh` has no row here, when a row names a mode that no
longer exists, when any tracked `*.spec.*|*.test.*` file (whole repo) is run by no gate, or when CI stops invoking `scripts/dev/test-node.sh`. Nothing may exist that
no gate runs (PROCESS.md, unit maintainability). Evidence labels follow `AGENTS.md` (DESIGN, MODEL_ONLY,
MOCK, SANDBOX, LIVE, NOT_RUN): a pass here is only ever as strong as the label in its "proves" cell.

`--browser-click-sweep`: `TestBrowserClickSweep` (`tests/foundation/browser_click_sweep_test.go`) builds ONE stack on the `tcvNew` harness: production admin Next (signed MOCK IdP, merchant password login on beside it, store creator = owner staff role + the whole permission catalogue), production storefront Next behind a synthetic TLS edge (`https://buyer.example`), the real Go API with every optional surface mounted (CVS + ECPay fake, bank transfer / COD settings, promotions, manual orders, Studio + claims, Meta connect over the loopback fake Graph with one connected MOCK Page, Meta ads and platform billing over fakes, provider accounts, store domains, staff team + loopback SMTP) and isolated PG 18, seeded through the real merchant/buyer paths (products + collections + a published design, COD / bank-transfer (proof submitted) / CVS bank-transfer / CVS pay-at-pickup (one with an ECPay label) orders, a promotion, a Studio scene). The runner `tests/ui/click-sweep.mjs` (library `click-sweep-lib.mjs`, unit tests `click-sweep-lib.test.mjs` run by test-node) drives Chromium; `page.evaluate` only reads/measures. Per control: a visible effect within 3 s (URL change, layer/disclosure opened, DOM or own-state change, validation, download, popup, external navigation answered by a stub), no new console error / page error / 5xx, hittable by Playwright actionability; the page itself must open without an error state. Output `output/ui-click-sweep/ledger.{json,md}` (page, viewport, locale, control, action, expected, actual, pass/fail), screenshots of failing controls, `journeys.json`. Alike controls (rows with ids) are sampled (3 per class, the ledger names the class size). `tests/ui/click-sweep-known-defects.json` is the explicit list of open defects (id, route, kind, control, severity, owner unit): it classifies failures, never silences them, and an entry that no longer reproduces fails the run (remove it when its owner unit lands the fix); the gate stays red until the list is empty. Not covered (NOT_RUN): refund and card-payment panels (no card-paid order in this stack; `--browser-refund-fulfilment`), real FB/IG dialogs, real PSP/carrier pages, WebKit/iPhone Safari (`--browser-webkit`). Developer affordance: `LC_SWEEP_ONLY=admin,storefront,journeys`, `LC_SWEEP_PAGES=<route substrings>`, `LC_SWEEP_WORKERS`, `LC_SWEEP_HOLD=<s>` (keeps the seeded stack up and writes `runner.env`).
  Protocol links (`tel:`/`mailto:`, integrator 2026-10-03): the real click still runs and errors still fail; the OS handler is not observable headless, so a well-formed href (`protocolHrefOK`, unit-tested) passes with a note and a malformed one fails as `bad-protocol-href`.

## Accepted NOT_RUN (R1)

`scripts/dev/release-gate.sh` labels a NOT_RUN row `(accepted: <reason>)` only when every item it names is in
its catalogue (function `accepted_notrun`); every other NOT_RUN is labelled `UNACCEPTED:`, keeps the overall
line INCOMPLETE and makes `--strict` exit 3. The catalogue is exactly:
