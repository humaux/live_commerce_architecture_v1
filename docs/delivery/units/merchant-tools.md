## Scope
1. Dashboard = the admin landing (`/[locale]` after login; keep the Ledger reachable from nav): today / 7 days (Asia/Taipei) orders count, GMV by payment mode (captured, confirmed transfers, collected pickup — reuse finance definers, no second ledger), to-do counters with links (awaiting transfer confirmation, to ship, CVS awaiting label, low-stock SKUs, open refunds), latest 10 orders. Read-only, one SQL definer per block, ≤ 300 ms on 10k orders (index check).
2. Product CSV: export (UTF-8 with BOM for Excel, one row per variant: handle/slug, title, description, status, option1..3 name/value, sku code, price, compare_at, stock per warehouse, collections, image count) and import (same columns; creates or updates by slug + sku code; dry-run preview listing every row error with row number before commit; all-or-nothing commit in one transaction per file ≤ 5,000 rows / 2 MiB; new products default draft; never deletes; stock via the inventory adjustment path with reason "csv import <file sha256 prefix>"; idempotent on re-upload of the same file). Images are not imported (document).
3. Manual order (後台建單): merchant picks SKUs + quantities, customer name/phone/email, delivery (home address or CVS store entered), payment mode bank_transfer or pay_at_pickup (no card), optional note; server quotes (same quote path; merchant cannot override prices — a manual discount needs promotions unit, out of scope), reserves stock through the same begin path, creates the order with `source=merchant_manual` (order source must be persisted for attribution), and returns a buyer order link the merchant can paste into LINE/Messenger (existing buyer order capability).
