## Scope
1. Admin Settings card 「Facebook 主頁 / Instagram」: Connect → Facebook Login for Business dialog (config_id from env `COMMERCE_META_LOGIN_CONFIG_ID`, scopes as fallback: pages_show_list, pages_manage_metadata, pages_read_engagement, pages_messaging, instagram_basic, instagram_manage_comments, instagram_manage_messages, business_management) → callback (state bound to store+principal, single use, 10 min) → server exchanges code, checks granted permissions (/me/permissions), lists Pages (/me/accounts with tasks; require MESSAGING + MODERATE tasks) and each Page's `instagram_business_account` → merchant picks one Page (and its IG if present) → server seals the Page token, registers the binding for this store, POST /{page_id}/subscribed_apps?subscribed_fields=feed (IG comments/live_comments come via the app-level instagram subscription), creates/updates the claims route → card shows Page name/id, IG username, permissions granted, token status, last webhook received time; Disconnect (DELETE subscribed_apps best effort, binding disabled, token destroyed, audited); Reconnect when expired/revoked (a Graph 190 error flips status to `reauth_required`).
2. Missing permission / task → clear message listing what to re-grant; never partial-enable.
3. One Page can be bound to only one store platform-wide (409 otherwise, no leak of the other store).
4. Env/config: preflight requires `COMMERCE_META_LOGIN_CONFIG_ID` + redirect URI when the meta profile is on (follow how ads adds its OAuth env); deploy/env example + runbook merchant-onboarding.md step "連接 Facebook 主頁"; document the Meta dashboard settings the owner must set (Valid OAuth Redirect URI `https://<admin host>/api/meta/callback` or the path you choose, Login for Business configuration with the scopes above) in docs/runbooks/deploy.md §Meta.
5. Studio: when no Page is connected, the claims source picker links to this Settings card instead of a dead end.
