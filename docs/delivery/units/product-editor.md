### 1. 发布流程

入口页 `offer.1688.com/offer/post/post_navigation.htm`（`01-post-navigation.png`）：

- 写明三步：「1.选择类目→2.填写商品详情→3.提交成功，等待审核」。
- 点「我要发布商品」进入 `offer-new.1688.com/select.htm`。

`select.htm` 有三种发品方式（`02`、`03` 截图）：

| 方式 | 内容 |
|---|---|
| 以图发品（默认标签） | 先传 4 张主图和 1 张白底图，再传「补充信息」：规格图/表、其它最多 10 张。点「AI预测」后，自动识别并预填商品信息。附主图优质示例：不低于 800×800。 |
| 类目发品 | 先选商品类型（现货 / 加工定制），再选类目。类目有搜索框（可文字，也可拍照搜）。有「常用类目」chips（最近用过的）。有一级到多级的级联类目树。「确认类目 继续完善」在选定前是灰的。另有「复制已发布商品」和「草稿箱(0)」。 |
| Excel发品 | 批量上传。 |

### 2. 表单信息架构

`offer-new.1688.com/popular/publish.htm?id=<offerId>&operator=edit` 是单页长表单，页面约 4250px 高，没有分步。

- **新发、编辑、复制用同一页**：编辑是 `operator=edit`，「发布相似品」是 `operator=import`，都是 `fill_product_info.vm?…&offerId=`。
- **顶部**：「您选择的类目」面包屑加「修改类目」，供货方式（现货/定制），重点经营渠道。
- **区的顺序**：主图视频 → 基础信息 → 销售信息 → 服务与承诺 → 物流信息 → 渠道特色信息 → 详情信息。
- **左侧 sticky 面板**：
  - 星级质量分（五星）和「刷新」；
  - 「错误(0) / 待优化(3)」两个页签；
  - 区导航，每区显示「已完成」或「N个待优化」，可展开看具体建议，当前区高亮。
- **底部 sticky 栏**：条款链接、「同意协议条款，我要发布」、「访问商品」。编辑页没有保存草稿按钮。
- **必填与提示**：必填项用红星。字段旁有计数（`58/60`、`0/50`）。有说明文字，例如「产品属性描述错误或不完整，可能会导致商品审核不通过」。

### 3. 图片和视频

- 主图列表是可排序的 `picture-sort-list`，有 4 张。
  - 第一张带「首张主图」角标。
  - 每张有「删除」叠层。
  - 满 4 张后上传格被隐藏（DOM 里有一个 `hidden` 项）。**主图上限 4 张是据此推断的，没有直接看到文案。**
- 首张主图要求 800px 以上实拍大图，包含整体款式和细节。
- 白底图单独一格：比例 1:1，800px 以上，小于 5MB，PNG/JPEG/JPG/BMP，纯白底，不能有 LOGO 和文字，旁边有「抠白底图」。
- 另有主图视频（5 秒以上）和商品讲解视频（300 秒以内，建议 9:16）。

### 4. 标题与属性

- 标题计数是**字节**：我的实例 58/60，汉字算 2。
- 属性由类目驱动（是否进口、产地、品牌、原料成分、功能、香味……），必填带红星，文本类带 `0/50` 计数。
- 可加最多 3 个自定义属性。属性区可「收起更多属性信息」。
- 基础信息和销售信息各有「模板」：选择、更新、存为新模板。

### 5. 规格和 SKU

- 规格维度一行一个（香型、净含量）。每个值是一个 chip，带 × 和「删除」，后面有一个「+」按钮（作用没点开）。
- 维度标题旁有「排序」「去重」。输入框带联想（「请输入或选择香型」）。
- 规格值和 SKU 表**实时联动**，没有「先保存规格」这一步。
- SKU 表列：序号 | 规格 | 规格图片 | 可售数量 | 累计订购数量 | 单品货号 | 69码/UPC | 是否上架。
  - 每个可填的列头都有「批量设置」。
  - 每行「是否上架」是开关。
  - 表下方一行：「上架售卖库存合计7000瓶」和「全屏编辑」。
- 批量设置弹窗（`12-batch-set-qty.png`）：
  - 选择范围：全部（下拉）。
  - 两种方式：「相同数值」或「批量计算」（增加/减少 + 数值）。
  - 提示「计算结果不符合商品规则的会自动跳过，例如单价、可售数量为负数」。
  - 三个按钮：确定并关闭 / 确定并继续 / 关闭。
- 「按产品规格报价」是另一个单选项，我没有切换，所以每个 SKU 单独定价的界面是**推断**的。

### 6. 价格和库存

- 价格显示为 `¥ 46.00`、`38元/瓶`，有计量单位（瓶）。
- 报价方式是「按产品数量报价」（区间价）或「按产品规格报价」。
- 隐藏区还有：最小起订量、1 件采购价（用于拿样、代发、零售）、批发价折扣系数。
- 库存：可售总量，「库存扣减设置：下单时扣减 / 支付时扣减」。每个 SKU 货号/UPC 有 `0/100` 计数。

### 7. 描述编辑器

- 富文本，有「手动编辑模版 / 智能编辑器」。
- 工具栏含商品描述模板、插图、表格、全屏、优化排版、字体、源代码。
- 可「保存为我的模板」，可插入详情视频。

### 8. 物流

- 发货地址（选择，可管理，可刷新）。
- 运费：「使用运费模板」加一个模板下拉。
- 「件重尺」：长/宽/高(cm)、体积、重量(g，必填)。可「按规格设置」或「按商品设置」。有「实测图验真」推荐项。

### 9. 发布选项

- 「上架时间」（必填，页面内置配置里读到）：「立即上架」或「定时开售」。
- 定时开售的帮助文案：开售前旺铺、搜索、详情页买家可见，开售后正常售卖。
- 「售卖方式」：普通售卖 / 批量售卖 / 混批。
- 草稿：有「草稿箱」，在列表状态页签和类目页入口。这次没有看到「保存草稿」按钮本身。

### 10. 编辑流程（商品管理 `offer.1688.com/app/pages-group/manage-home/index.html`，`04` 截图）

- **列表状态页签**：全部 / 销售中(67) / 库存售罄 / 待上架 / 审核中 / 违规下架 / 草稿箱 / 回收站。
- **筛选**：现货/定制切换、智能筛选 chips（带数量）、按商品 ID / 标题货号 / 自定义分类 / 渠道搜索，另有「高级搜索」。
- **批量栏**：「已选 N 个商品」，操作为 **下架**（主按钮）/ 删除 / AI智能属性填充 / 更多操作。更多操作里有：设置自定义分类、批量设置发货时效、批量设置官方定制项等 8 项。
- **列表列**：商品名称（带封面、货号、ID、质量分星级）、价格、库存、流量、成交、更新时间、AI 诊断、操作。
- **行内编辑**：标题、价格、库存各有一个铅笔图标，点开是「修改价格库存」弹窗（`06` 截图）：
  - 上半部分是价格；
  - 下半部分是库存：当前总库存、「批量修改」行（全部 SKU / 设为或增减 / 数量）；
  - 再下面是 SKU 表：当前库存 | 加/减切换加数量 | **改后库存（可直接填）**；
  - 底部：取消 / 确认。
- **行操作**：修改详情（同一表单）/ 发布相似品（复制）/ 一键推爆。
- 入口页另列了「商品快速编辑」「商品批量修改（支持多条一次编辑、一键还原、定时）」「复制搬家」。

## c. 新增 / 编辑页设计

### c1. 总原则

1. 一页同时承担新增和编辑，`mode = create | edit`，照 1688 的 `operator=edit`。路由沿用 `/{locale}/products/new` 和 `/{locale}/products/{id}`。
2. 保存是一次幂等的「商品文档」命令。商品、规格、SKU、库存、关键字、分类一次提交。
3. 状态由底部操作栏决定，不再单独保存。
4. 服务器仍是唯一的裁判，客户端校验只是为了省一次往返（和 `ProductEditor.tsx:8-9` 的写法一致）。

### c2. 页面布局

**桌面**

- 左栏 sticky，约 220px：
  - 区导航（带锚点和滚动高亮）；
  - 下面是完成度清单。
- 右侧是卡片，按下面的区顺序排。
- 底部 sticky 栏放主要操作。

**手机（375px）**

- 左栏变成顶部横向 chips，区卡片单列。
- 底部栏吸附在屏幕底。
- 不出现横向滚动。矩阵表在手机上每行渲染成卡片。

### c3. 区顺序、字段与数据模型映射

| # | 区 | 字段 | 映射和规则 |

### c4. 左栏完成度清单（替代 1688 的星级）

- **必填**（不齐不能上架）：≥1 张图、名称、售价、库存或 ∞。
- **建议**：≥3 张图、描述、分类、关键字、SEO。
- 显示「还差 N 项必填」。每项点击滚动并聚焦到对应字段。
- 有错误的区在导航里标红点。这对应 1688 的「错误 / 待优化」两个页签。

### c6. 底部操作栏和保存机制

| 场景 | 操作 |
|---|---|
| 新增 | 「保存草稿」「上架」 |
| 编辑草稿 | 「保存草稿」「上架」 |
| 编辑上架中 | 「保存」，更多（⋯）里放「下架（转草稿）」「封存」「复制」 |
| 编辑已封存 | 「保存」「恢复为草稿」 |

**保存命令**（一次幂等、同一事务，可编辑页复用）：

```
create: POST products
edit:   PUT  products/{id}/document   (expected_version)
{ name, description, status: "draft"|"active", slug?, seo_title, seo_description,
  options:[{name,values[]}],
  skus:[{ id?, option_values[], code?, price_minor, compare_at_minor|null,
          stock:{ mode:"tracked"|"untracked", opening_qty? | target_qty? },
          keyword?, active }],
  collection_ids:[], weight/dims }
```

- 关键字冲突、slug 冲突、combo 重复，都在整个事务内回滚，不留半个商品。
- 已有订单的 SKU 在轴变更时由服务器按「归档」处理，客户端先弹确认「N 个规格将归档」。
- 库存「改后库存」写入时，由服务器按目标值和余额版本算出差值，原因默认「后台编辑」。库存页保留「必填原因」的显式调整。

**图片和提交的时序**（图片路由需要先有商品 id）：

- **方案 A（建议，不加新表）**：新增时图片先留在本地，标「待上传」。
  1. 点保存，先以草稿状态一次建好文档；
  2. 再逐张上传、排序；
  3. 若请求的是上架，最后再翻成 active，买家不会看到没图的商品。
  4. 用户看到的是一次点击，加进度条（3/5）。上传失败时商品已在草稿里，可点「重试」继续。
- **方案 B**：暂存上传表（带清理任务），需要新表，留给后续。
- 编辑模式下图片操作沿用现有路由，即时生效。

**其它保存行为**：离开页面有未保存改动时给浏览器级提示，不做本地草稿缓存。

## e. 验收 gate（浏览器加 PG，每项先红后绿；结果须标 MOCK/SANDBOX/LIVE）

### PG（数据库和契约）

- **PE01 单次保存**：一个 `product.save` 创建商品、3 个 SKU、期初库存、关键字、2 个分类，同一事务。中途任一步失败，没有任何残留行。
- **PE02 幂等**：同 key 同字节重放返回第一次结果，不重复建；同 key 不同字节返回 409。
- **PE03 关键字和 slug 冲突**：冲突时整体回滚，错误码分别是 `keyword_taken`、slug 409。
- **PE04 金额**：输入「60」存成 6000；「60.5」对 TWD 拒绝；读出 `NT$60`。
- **PE05 不追踪**：对不追踪 SKU 并发 100 单不报库存不足；对追踪 SKU 最后 1 件仍不超卖（A6，K3 测）。

- **PE08 轴变更**：已有 SKU 被轴变更搁浅时按「归档」处理，订单历史保留；重新创建同组合可行。
- **PE09 乐观并发**：过期的 `expected_version` 返回 409，不静默覆盖。
- **PE10 隔离**：另一租户或店铺读写这些行都是 404（CC10 的回归）。
- **PE11 批量状态**：100 个 id，逐个返回结果，部分失败不影响其它。

## g. 集成者裁决：编辑语义（2026-10-03，product-ui 停工线的后端补口）
来源：`output/product-ui/REVIEW.md`（unit/product-ui 42221139）的 Backend blockers 1–2，已在 product-core-tests e904ce5 源码核实。
按 PE14「只带改动」和 PE15，编辑命令改为合并补丁（merge-patch），新增商品命令保持整份文档不变。

**裁决**
1. **编辑 = 合并补丁**（`expected_version ≥ 1`，operation 仍是 `product.save:<id>`，同一个 `command.Run` 事务，需要 Idempotency-Key）。
   - **顶层字段看「是否出现」**：没出现就保留原值；出现了就覆盖。适用于 name、description、status、slug、seo_title、seo_description、options、collection_ids。
     - `collection_ids: []` 表示清空，不出现表示不动。
     - 实现时用指针或 `json.RawMessage` 判断出现与否，不能用零值猜。
   - **`skus` 不出现**：任何 SKU 都不动。
   - **`skus` 出现时**：
     - 带 `id` 的条目只改它给出的字段：price_minor；compare_at_minor（显式 null 表示清除）；stock；keyword（`""` 表示清除，不出现表示不动）；active；option_values；origin_country、customs_name、hs_candidate；以及第 3 条的单 SKU 物流字段。
     - 不带 `id` 的条目是新 SKU，按新增时的完整校验处理。
     - **没被提到的现有 SKU 一律保持原样。**
   - **归档 SKU 只能显式写 `active:false`**，不再靠「省略」。
     - 改了 `options` 之后，所有仍为 active 的 SKU 都必须符合新的轴，组合也不能重复，否则整笔返回 `invalid` 并回滚。
     - 要退役的 SKU 由客户端显式发 `active:false`。
   - **任何 SKU 改动都会让商品 `version+1`**，以 `expected_version` 防并发覆盖。
   - **幂等哈希用规范化后的补丁本身。** 审计只记被改字段的名称，不记字段值。
2. **库存目标值**：
   - 编辑时 `target_qty` 出现（**包括 0**），就把现有量设成目标值；不出现就不动。修 `document.go:213` 的 `*stock.qty != 0` 判断。
   - 新增时 `opening_qty` 为 0 仍然不写流水。
   - 目标值低于「已预留 + 已分配 + 不可用」时返回 `insufficient`，现有映射不变，不新增错误码。
3. **物流**：
   - 顶层 weight/length/width/height 只在新增时生效，作为所有 SKU 的默认值。**编辑时出现顶层物流字段一律返回 `invalid`**。
   - 编辑按单个 SKU 进行：SKU 条目新增 `weight_grams`、`length_mm`、`width_mm`、`height_mm`，类型为指针。界面的「列批量」逐个 SKU 填写。
4. **详情 GET 补字段**（`GetProductDetail`）：
   - 商品级 `collection_ids`：全部成员，不分页。
   - 每个 SKU 的 `keyword`：`""` 表示没有。
   - 商品级 `warehouse_id`：店里**恰好 1 个**启用仓时为该仓，否则为 null。
   - 每个 SKU 的 `on_hand` 和 `committed`（committed = reserved + allocated + unavailable）：只在 `warehouse_id` 非 null 时给出，取自该仓，否则为 null。
   - 现有的 `available` 保留。
   - `warehouse_id` 为 null 时，界面禁用「改后库存」，并说明原因、链接到库存页。不能用 `available` 冒充现有量。
5. **开放中的直播窗口**（沿用 §f.3 的判断：OPEN 窗口里有 active offer 的 SKU）：
   - 编辑时下列操作逐项返回 `live_window_open`，整笔回滚：
     - 把商品改成非 active；
     - 对窗口内的 SKU 写 `active:false`；
     - **改或清空窗口内 SKU 的 keyword**（留言匹配依赖它）。
   - 改价允许：直播价在场次里单独生效，目录价只影响非直播买家。
6. **列表**：搜索、状态页签、计数和游标分页都已在服务端实现，就以服务端为准，不做本页过滤。
   - 排序只有 updated_at 倒序。
   - 视觉稿里的其他「智能筛选」没有后端支持，**不画**（W0「没有行为的控件不出现」）。
7. **行内快改**（PE15）：用同一个编辑命令发单 SKU 补丁，例如 `{expected_version, skus:[{id, price_minor}]}`。
   - 只有单 SKU 商品可以在行内直接改。
   - 多 SKU 商品点铅笔，打开该商品 SKU 列表的浮层（读详情），在浮层里逐个 SKU 改。
