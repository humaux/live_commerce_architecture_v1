# 双后台、买家端与多商户隔离

2026-09-20。用户要求完整SaaS：**平台管理后台 + 商家经营后台 + 买家独立站**，不是几个Meta接口。本文把M01/M20/M21和界面、权限、生命周期落成可开发清单；状态为DESIGN，未部署。

## 1. 产品结构和导航

可以同仓库、共用组件与Go API，但三套权限域不能共用一个“超级管理员”开关。下述是建议页面结构，路由在T01冻结，不是现有页面。

|端|主要菜单/页面|能完成的工作|
|---|---|---|
|平台P01 总览|活跃/试用/受限租户、订阅收入、外部故障、待办|运营概览按权限聚合；不默认展开顾客私信/地址|
|平台P02 租户管理|租户列表、开通/邀请、详情、套餐、店铺/人员数量、限制与恢复|管理租户生命周期；查看影响预览、确认及审计，不能一键删交易|
|平台P03 套餐与权益|套餐版本、席位/店铺/存储/消息等额度、试用/升级/降级|计划变更生效时间明确，旧合同/历史账单不可被覆写|
|平台P04 账单与用量|用量账本、SaaS账单、支付状态、欠费/争议、导出|只管理平台服务费；商家商品货款与跨境COD不进同一资金池|
|平台P05 渠道/供应商中心|Meta应用级健康、租户绑定/能力状态、物流/PSP接入、限流/故障|查看连接与脱敏诊断；密钥不可明文列表；租户授权单独保存|
|平台P06 域名与模板中心|域名验证/TLS故障、模板/区块版本、兼容检查、发布灰度|发布平台模板能力不直接覆盖各商家装修；可回滚平台版本|
|平台P07 任务/通知/异常中心|失败/未知外部操作、积压、备份、告警、事件对账|有权限、范围和前置条件才重试；未知扣款/消息不能强制盲重放|
|平台P08 支持与工单|商家工单、脱敏诊断、限时支持授权、操作轨迹|先授权后代查；默认只读；到期回收，禁止共享商家密码|
|平台P09 安全与合规|平台人员角色/MFA、审计、隐私请求、留存、异常访问|平台运维/财务/支持权限拆开；重要操作可复核；删除不绕保留义务|
|平台P10 系统运营|版本/SBOM、发布/回滚状态、服务状态、运营通知、全局能力开关|配置变更有审批/影响面/回滚；不能因维护或欠费暗停客户直播|
|商家B01 工作台/开店向导|待发货、待回复、缺货/异常、开店检查|缺配置显示原因和下一步，不由开发者逐店代填|
|商家B02 店铺/员工设置|店铺资料、语言/币种/时区、成员/角色/审计|所有操作限制在所属店铺，所有者权限不等于平台权限|
|商家B03 商品与库存|商品/SKU/分类/媒体、价格成本、导入、库存调整/仓库|商家自己维护商品，冲突/无效数据可恢复|
|商家B04 网店装修|主题、首页区块、导航、商品集合、政策/SEO、移动预览、发布历史|无需代码自行装修；编辑/发布权限可拆，回滚不碰交易|
|商家B05 渠道与账户|Page/IG授权、资产选择、能力诊断、物流账户/轨迹服务、支付账户|自带渠道/收款/物流；逐连接查看健康与撤销影响|
|商家B06 直播销售|场次、商品词库、专属价、消息模板、评论台、推流/回放（获权时）|业务场次和外部直播控制分开，危险操作显式确认|
|商家B07 贴文/机器人|贴文活动、词库、机器人草稿测试发布|状态可见、停用规则不删除外部帖子|
|商家B08 客服收件箱|网站咨询/订单沟通与FB/IG分栏；分配/未读/接管/备注、客户及购物车侧栏、手工单|站内和渠道消息独立，渠道合法窗口内发送；列表聚合不串权限，详见08|
|商家B09 订单/收款/售后|订单详情、付款/履约/退款分状态、部分退款、RMA、对账|任意状态不能靠随手改字段跳过资金凭证|
|商家B10 配送/运单|配送地区/运费/超商选店、跨境账户、外部运单录入/批量导入、面单（可用时）、轨迹/异常|不强迫用平台买物流；自行发货也能关联买家查询|
|商家B11 客户/会员/促销|客户关系、标签/分群、同意/删除、优惠规则及批准的会员深度|收款事实不自动给营销同意；身份关联可撤销|
|商家B12 数据/广告|成交/净额/利润/活动漏斗、广告草稿/预算审批、Pixel/CAPI|可追踪来源，数据延迟和未知归因不隐藏|
|商家B13 套餐/账单/用量|自己的订阅、支付、用量、升级/续费|不能查看别家账单；降级前预览影响|
|商家B14 导入导出/支持|订单/包裹筛选、收货资料批量导出、承运商模板、运单批量回填、迁移/错误报告、帮助工单|导出也查权限，文件有期限，支持访问随时撤销|
|买家C01–C06|首页/集合搜索、商品、购物车、结账选店、订单与物流查询、售后/隐私|新站完整交易、超商自动回填、查看自己包裹，不需了解平台/物流供应商后台|
|买家C07 联系商家|网站咨询入口、订单沟通、消息历史/未读/受控图片、断线恢复|游客咨询与已验证订单访问分开；无需FB登录，Meta故障不阻断站内客服|

会话边界按[08专题](08-会话分域与业务架构调整.md)执行：B08可复用视觉组件和订单工具，但原生webchat、Meta渠道、平台支持工单、认证session的记录/授权不可混合。平台P08支持流程不得透传买家私信；买家C07另有CS01–CS14门禁，不以“联系商家入口可见”替代收发验收。

信息结构验收：订单不与直播场次共用一张混乱列表；商品维护与装修不复制同一套数据；“已连接”不掩盖逐能力失败；业务状态/空态/加载/错误都有可操作反馈。不要用多个内容相同的卡片代替完整页面。

## 2. 权限矩阵

`允许`仍须对象/租户/店铺范围及业务前置条件。表中“支持授权”是限时只读为默认的受控访问，不是全库万能权限。

|动作|平台运营|平台财务|平台支持|商家所有者|商家商品/装修|商家客服|买家|
|---|---|---|---|---|---|---|---|
|创建/限制租户、平台套餐|授权允许|只看账单相关|无|仅申请自己的开通/变更|无|无|无|
|查看平台SaaS收入|有限聚合|允许|脱敏状态|只看自己订阅账单|无|无|无|
|商品/装修草稿|无默认权|无|支持授权只读|本店允许|本店授权范围|只读所需商品|仅公开内容|
|装修发布/回滚|不能代商家静默发布|无|另行明确授权才可写|本店允许|需发布权限|无|无|
|商品订单/私信/客户PII|无默认全量权|无默认全量权|最小化支持授权|本店且按目的|最小必要字段|本店分配范围|仅本人可验证订单|
|退款/广告花费/物流建单|无默认权|不能替商家动款|默认禁止|独立权限及确认|独立授权才有|默认禁止|只能申请售后|
|注册外部运单/看轨迹|平台只看系统健康|无|支持授权|本店允许|仓库履约权限|允许所分配订单查询|仅本订单包裹|
|安全/隐私删除/导出|指定职责和审计|财务合规范围|只处理工单允许范围|本店受规则约束|无默认权|无默认权|申请本人数据请求|

实际角色为可管理权限集合，不写死“客服就拥有所有订单”。平台人员身份与商家成员身份分别登记；同一个自然人兼任两者也必须切换明确上下文。

## 3. 租户生命周期与运营闭环

推荐状态：申请/邀请→开通中→试用/正常→受限→恢复/终止待处理→按留存规则关闭。开户幂等，创建一半失败可恢复，不能留下跨店默认管理员。

- 开店检查逐项记录商品、装修、域名、政策、支付/物流及渠道资格。普通网页营业资格与Meta直播自动化资格分开，后者未获批不冒充可用。
- 套餐变更有版本和生效点；降低席位/额度先预览超限资源，再按规则处理，不自动删人员数据或库存。
- 欠费/风控限制应区分“禁止新建资源/新销售”与“已付订单履约、退款、买家查单、数据导出”。不能把商家整个系统无解释封死，更不能为订阅欠费直接关闭既有直播。
- 支持人员申请范围、原因、期限和工单关联；商家授权后才代查，默认脱敏/只读，授权撤销立即生效。紧急访问需单独制度、权限和审计，不留隐藏后门。
- 租户关闭先停新增副作用、清点在途订单/物流/外部操作、导出和结算，按保留策略处理；不能级联物理删除金融/审计事实。
- 平台需要查看故障、告警、用量、供应商资格、回滚和备份结果，不能只有数据库脚本才能运维。重放任务要显示将影响的租户/订单/外部调用及幂等状态。

## 4. 全链隔离设计

|层面|隔离要求|必须失败的负例|
|---|---|---|
|认证与会话|平台/商家/买家受众和对象授权明确；切店重新验证membership|把URL或JSON的store_id换成别家的仍可访问|
|PostgreSQL|tenant/store键、作用域外键/唯一约束与RLS；普通运行角色不能绕RLS；事务作用域/连接池重用正确复位|漏WHERE或重用上一租户连接泄露行；子表引用别家父对象|
|后台任务|可信事件/资产绑定解析租户，worker执行时重验授权与版本|伪造job tenant或撤权后旧任务仍发送/退款|
|Webhook与供应商|验签/合同校验后按账户/asset映射到租户；错环境/错账户拒绝|仅信任payload传来的tenant_id或名称|
|缓存/搜索/报表|scope/语言/市场/币种/版本参与键；个性化查询不公共缓存|同路径同SKU代码导致A看到B的价格/客户/报表|
|文件/媒体/导出|对象权限及授权下载、必要期限；公开商品与私密订单/录像分层|猜对象key访问别店导出；公开CDN暴露会话附件|
|SSE/WebSocket|订阅对象授权和断权撤销，按店铺topic隔离|切店后旧订阅仍读别店评论/订单|
|密钥与日志|凭据按绑定加密/受控取用，日志脱敏；平台诊断最小字段|将所有商家Meta/物流token放前端或平台表格|
|流量与任务队列|每租户公平性、速率、并发和用量计费准确|一个大直播淹没其他商家结账/客服|
|备份/恢复/隐私|整体恢复与租户级导出操作分权，恢复后仍保留隔离/删除标记|恢复旧备份复活已撤销授权并自动重发任务|

这些不是“加tenant_id字段”即可满足。每个模块写入前都要落实接口作用域、数据库约束和负例；禁用RLS的迁移/维护角色不能拿来跑普通API。

## 5. 商家自带物流与买家查件

用户已确认商家一般不使用平台物流。平台应提供统一追踪能力，不强迫转用平台承运合同，不把平台变成承运商。

- **建单能力**：仅已授权、适配器支持的商家物流账户可建单/取面单；默认不会因为填写单号就新建另一个物流订单。
- **追踪能力**：商家即使在别处发货，也能在本店订单录入/导入/通过其系统API同步“承运商、原始单号、包裹行、始发/目的地、发货时间”。后端校验关联与重复，按供应商能力注册查询/订阅。
- **来源层级**：商家承运商API或其授权Webhook优先；可选轨迹聚合服务用于已覆盖线路；无API时提供可信官方查询入口或有来源标识的人工状态。是否使用聚合服务需范围/费用/隐私确认，不默认开通服务。
- **跨境多段**：一个包裹可以有头程、清关后台湾末端等多个运单；同一单号在不同承运商/账号下不能当同一包裹。保存原始状态及规范化展示、来源时间/抓取时间；乱序/重复更新不得随意把已签收倒退为运输中。
- **买家入口**：新站订单详情/安全查件链接展示包裹拆分、时间线、最新更新时间、超商门市/到店待取提示（有证据时）、未取/异常和联系商家入口；不用买家登录承运商后台。
- **访问安全**：登录订单授权或足够强的只读短期查件票据；仅凭可枚举订单号/手机号不能查全量信息。公开入口不显示完整清关身份、他人电话地址；不能直接请求用户任填的追踪URL造成SSRF/开放跳转。
- **诚实状态**：`未登记单号 / 已登记待承运商揽收 / 暂无轨迹 / 更新延迟 / 运输中 / 到店待取 / 已取件 / 异常`分别表示；手工填写“已发货”不冒充供应商已揽收；查询API成功但无事件不伪造事件。
- **更新机制**：有Webhook则验签/持久化/去重；按服务商规则用限频查询补缺，有退避、终态停止或降低频率、费用额度；不让每个买家刷新都触发一次昂贵供应商请求。
- **通知与COD**：买家订单页始终可查。Messenger通知仍过Meta用途/窗口门禁；“到店”“签收”“COD已代收”“已结算”不可互换。轨迹聚合一般不能单独证明商家的代收款已入账。

商家迁移无须改现有物流商才能使用查件，但**每个承运商/入台线路的轨迹覆盖仍需实测**。不承诺一个聚合API支持所有中国大陆及台湾专线。

官方可行性参考：[SHOPLINE Tracker](https://support.shoplineapp.com/hc/en-us/articles/20380041710489-Tracker-App)明确允许非集成物流手动关联承运商和运单；[17TRACK API](https://api.17track.net/en/doc)及[AfterShip Webhook](https://www.aftership.com/docs/tracking/webhook/webhook-specifications)提供轨迹注册/更新机制。这里只证明有此类合法技术路径，不表示已购买、已接入或覆盖客户实际线路。

### 5.1 批量收货资料导出与外部履约回填

这是商家日常核心流程，不是仅为第一次迁移做一次CSV。由M14/M15/M22负责，商家B09/B10/B14可进入同一批处理中心。

|环节|必需功能与字段|验收约束|
|---|---|---|
|选择订单|按店铺、下单/付款时间、付款/履约状态、渠道/活动、物流方式、标签、指定订单勾选；显示全筛选数量与排除原因|不把“当前页全选”默认为所有订单；全筛选需明确确认；取消/退款/已发货可排除或清晰标记|
|包裹与模板|XLSX/CSV；默认发货清单（每包裹一行）和商品明细（每包裹行一行）分开；承运商模板版本/列映射可保存|不因一单多SKU把地址重复当成多包裹；拆合包行和数量可核对|
|收件资料|订单/包裹ID、收件姓名、联系电话、国家/地区/邮编、宅配地址；或超商品牌、provider/线路、门市原始代码/店名/地址|使用订单已确认收货快照，不用客户档案最新地址覆盖历史订单；店号/电话/邮编为文本保留前导零|
|履约必要字段|SKU、品名/规格/数量、重量/尺寸（有据）、付款方式、COD应收/币种、商家履约备注|缺字段报告，不猜报关品名/重量；内部客服私密备注/营销画像默认不导出|
|预览与授权|选择字段/模板、脱敏预览、总行数/订单数、用途和操作者；独立PII导出权限|平台管理员无默认跨商家导出；不能仅以列表可见权限拿完整地址库|
|异步作业|排队/运行/成功/部分失败/失败/取消/过期，稳定快照或明确截止点、进度、错误报告和可重试批次|不丢不重行；不能只导出前端已加载几十条冒充全部；导出本身不标已发货、不减库存|
|文件安全|私有存储，鉴权下载、短有效期、审计；XLSX文本类型/CSV转义和公式注入防护；UTF-8及繁中兼容|不把PII放公共CDN/日志/邮件附件默认群发；撤权/过期后服务器拒绝新下载；已下载到本地的副本无法远程保证擦除|

大批量上限/行数/时限和并发由T19按真实客户量级冻结并压测；不编造“无限导出”承诺。普通收货导出不默认包含身份证/清关证件；确需时按承运/报关合同及严格权限单独最小化处理。

### 5.2 商家自助金流/物流设置

用户截图确认：供应商服务卡片需要账户连接、编辑、启用和买家可见性控制，
