# 功能模块与验收

版本：2026-09-20 需求补充候选。本文是待实现合同，不代表功能已上线。原 R01–R22 均保留；原任务/门禁没有被本表改写。

## 1. 产品边界和角色

这是**多商家自助建站与交易 SaaS + 社交直播销售渠道**。不是只给运营人员用的评论机器人，也不是一个跨店共用购物车的大商城。一个租户可经营多个店铺，资产/订单/账单不得跨租户串联。三端页面、平台运营生命周期与全链隔离详见 [双后台专题](07-双后台与多商户隔离.md)。

|角色|自己完成的工作|明确不能做|
|---|---|---|
|平台运营者|套餐、租户状态、集成健康、审计、工单和受控支持|默认浏览所有买家私信、替商家收款或无审计越权|
|商家所有者|创建店铺、邀请员工、商品、装修、绑定 Page/支付/物流/域名、营业配置|查看其他商家数据；把平台 App 密钥填到店铺前端|
|商品/仓库人员|商品规格、价格、库存、发货、退货验收|默认取得退款/渠道授权/广告预算权限|
|主播/助播|建销售场次、选商品、启用关键词、看评论/业绩；有权限才控制推流|结束其他场次或修改不属于自己店铺的直播|
|客服|分配会话、手工回复、草稿订单/购物车、内部备注和接管|绕过消息窗口、代买家同意营销、凭昵称合并身份|
|财务|付款、退款审批、对账、成本利润、平台账单|把订单状态手动改成已付款以替代支付凭证|
|买家|手机看商品、收到相关链接、改数量、选择配送、支付、查订单和售后|仅凭转发来的链接取得另一买家身份或私密信息|

商家自助开店主线：注册/邀请 → 建店和店铺资料 → 上传商品 → 装修草稿/预览/发布 → 配置收款、配送、政策与域名 → 通过营业检查 → 自主建直播销售场次。每步可保存草稿，缺少必需项显示可行动的阻塞原因。

## 3. 急需销售链路的细化合同

### FR-LIVE-01：经营场次不等于推流

- 商家可在未开播时配置销售活动、商品、关键词和消息模板，保存不可变发布版本。
- 对原生 Facebook/其他系统创建的直播，仅在授权且 API 探针通过后绑定视频 ID 和读取评论；不要求新系统重建/结束旧直播。探针失败明确阻塞，不能伪称兼容。
- 本平台开播是另一条受控路径；对现用 SHOPLINE 的安全策略是**不控制、不发送**，测试使用隔离 Page/测试场。
- 分别展示活动生效状态、外部直播状态、评论接入健康、消息发送资格；任何一个失败不把其余状态误报为失败/成功。

### FR-RULE-01：兼容操作习惯但不制造误单

- 保留原包精确口令和 `101+2 = 目标数量2`。客户现场“包含关键词+数量”是迁移兼容候选，不能擅自解释成累计增加。
- 匹配策略、关键词作用域、活动/商品启用、有效时间、数量上限、SKU/规格歧义都必须显式配置。可支持仅词、词+数量、限定包含模式，但宽松模式发布前必须过模拟器反例。
- 反例至少含“不买101”“101多少钱”“2101+2”“101+-1”、重复评论、多规格未选、停售/售罄、活动结束、旧规则重放。不明确的请求不自动生成可支付订单，转澄清/人工。
- 评论产生购买意图/草稿购物车，不直接扣款、不默认锁货。评论编辑/删除作为新事实保存；已有付款只能走退款/售后，不能被删评论撤销。

### FR-MSG-01：两条入口，不能混成无限自动私信

- A：针对合资格评论进行**一次首次私密回复**，放对应商品/购物车链接。受当前 Meta 许可约束，重试与模板换版不可重新获得一次额度。
- B：买家发来有效消息后，在实际会话窗口内接续客服/机器人；超窗重新评估允许用途，不能因评论存在而假设普通 Messenger 窗口已开启。
- 规则命中但不可发送时，保留意图及阻塞原因，不伪造送达。不默认改成公开回复，更不能向随机顾客测试。
- `SENT` 需平台返回可追踪 ID；`DELIVERED/READ` 需相应证据；网络未知状态进入核对，禁止盲目重发。

### FR-STORE-01：商家自助装修与真实交易

- 商家在自己租户内选模板，编辑首页区块内容/顺序、导航和推荐集合，设置 logo/颜色/页脚政策；商品内容由 M03 自动引用，不需要平台员工代改代码。
- 第一版采用**固定、版本化的安全区块**，不是自由执行 HTML/JS；仍需真实的编辑、预览、发布、回滚能力，不能拿一张固定首页当装修器。
- 商家发布主题前校验商品集合、图片/链接、安全、移动布局；模板切换先迁移/预览，不清空正在使用的装修；两个员工同时编辑要冲突提示。
- 结账留在新站交易体系，允许 PSP 托管支付页或安全支付组件，不是转回 SHOPLINE 结账。所有价格、税费、配送和库存由新系统重新核定。
- 最小页面集：首页、集合/搜索、商品详情、购物车、地址/配送/支付、结果/查询、售后入口、隐私/条款/配送退货政策。多语言/币种范围要冻结，不伪装全球覆盖。

### FR-CHAT-01/02：网站聊天与渠道会话分别闭环

- FR-CHAT-01：买家在网站咨询商品、从订单联系商家；访客可咨询，查看订单须验证；具备文本/受控图片、未读、离线保存、断线续读、客服分配/接管、内部备注。网站和订单咨询复用同一个webchat模块。
- FR-CHAT-02：登录会话、webchat、Meta社交会话、商家向平台的支持工单分别建模；客服界面和交易侧栏可复用，不能混用正文、身份/已读或发送资格。原R05仅社交范围不足以代表网站聊天已覆盖。
- 元素、字段/键候选、接口和CS01–CS14见[08专题](08-会话分域与业务架构调整.md)。本轮补的是设计，不是已实现数据库或聊天服务。

### FR-MIG-01：真实营业店迁移不能“开两边试试”

- SHOPLINE 与新系统同时存在时，未切换前新系统只能隔离测试或批准的只读影子比对，不能同时处理同一客户生产评论的自动私信。
- 商品/价格/库存需来源和截止时间，历史订单用外部 ID 映射且默认不可重开收款；营销同意和渠道客户标识不可凭导入补造。
- 切换需要客户确认商品库存、PSP、物流、域名与发送控制权。直播正在运行不自动停止；优先等客户选择安全窗口。
- 回滚必须说明新站已收款订单继续在哪里履约/退款、库存如何回写，不能仅把 DNS 指回去就称完成回滚。

## 4. 本轮验收范围

新增首发 **FR-TW-01**：中国大陆/境外→台湾，7-ELEVEN/全家按店号、店名或地图选店并回填。客户手工单/客服侧栏和买家结账共用选店组件，但权限各自验证；承运商支持的门市清单、代码体系、线路和付款方式是约束。门市资料不是普通宅配地址，选中不等于建物流单/付款。详见 [台湾专题](06-台湾超商选店与跨境履约.md)。

新增 **FR-TW-02**：在线已付与取货付款分流。COD仅在承运商合同允许时展示；订单成立/库存预留不代表已付款；取货代收、回款结算与退款分别留账。跨境清关/收件信息按真实承运商合同收集，不把超商门市地址当进口人身份资料。

新增 **FR-BYO-01**：商家通常自带物流，M15同时支持已接承运商建单与“仅同步/登记外部运单后追踪”，两者不绑定购买平台物流。买家C05必须可查本订单包裹轨迹/更新时间/异常；无覆盖明确显示，不虚构进度。

新增 **FR-EXPORT-01**：M14/M15/M22提供商家日常批量收货资料导出（宅配地址或超商门市、收件人电话等）、承运商版本模板、异步任务/错误报告/鉴权下载，以及外部运单批量回填。每包裹/明细粒度明确，导出不自动发货，详见07第5.1节及SA11–14。

本轮只验收：22 模块有责任边界和验收点；急需链路有正常/失败规则；现场/官网/设计推断来源分开；自助建站和新站交易未漏项。实际业务测试均 **NOT_RUN_PRODUCT**，执行门禁见 [开发计划](04-开发计划与门禁.md)。
