# SHOPLINE 商家后台对标研究（jie8888，2026-10-02，只读）

来源：owner 已登录的 SHOPLINE 后台 `admin.shoplineapp.com/admin/jie8888`（店铺「香港大碗貿易」，地区台湾），通过 Kimi 浏览器插件只读浏览。
未保存、未提交任何表单；未打开订单、顾客、消息收件箱（这些页面含买家个人信息）。下文中的店铺、Page 和供应商名称都是商家的业务数据，不是买家个人信息。

## 1. 整体架构：核心后台 + 按领域拆分的微前端

| 领域 | 实现方式（观察到的 URL） |
|---|---|
| 核心后台（商品、订单、设定、设计） | `admin.shoplineapp.com/admin/<handle>/...`，服务端渲染页面；商家 ID 是 Mongo ObjectId（`68f75a08…`） |
| 直播（SHOPLINE Live） | iframe `live-sale.shoplineapp.com/admin/<merchant_id>/live_admin` |
| 商品关键字、贴文销售 | iframe `post-sale.shoplineapp.com/admin/<merchant_id>/product_keyword`、`/SaleList` |
| 消息工作台（FB/IG/LINE/网店消息合一） | `message-center.shoplineapp.com/admin/<merchant_id>/inbox?platform_channel_id=...` |
| 社群建单 | `create-order.shoplineapp.com/admin/<merchant_id>` |
| Facebook 设定 | iframe `facebook-entrance.shoplineapp.com/?merchant_id=...&tabKey=basic-setting` |
| 支付 | iframe `payments.shoplineapp.com/merchant-entry/...`。它通过 SHOPLINE 自己的 OAuth 开放平台（`developers.shoplineapp.com/oauth/authorize`，scope 为 `openid permissions merchants staffs channels`）拿到授权，以自家 App 的身份接入 |
| 数据分析 | `dashboard.shoplytics.com/admin/<handle>` |

结论：SHOPLINE 用一个核心后台挂一批「自家 App」。各 App 是独立的子域和前端，通过开放平台的 OAuth 取得商家授权。这是平台规模、多团队协作下的选择。我们保持 Go 模块化单体加单一 PG（团队小、单店试点、需要强一致），只借鉴它的领域边界：直播、贴文、消息、Meta 渠道、支付各自独立成模块。

## 2. 商品（`/products/new`）

表单分 10 个区：主要图片（最多 12 张，建议 750×750）、商品信息、分类、数量和价格、商品规格、加购品、搜索引擎优化、设定、产品规格摘要、Metafields。

- **信息**：商品名称有英文和繁体两个字段（`product_name_en`、`product_name_zh-hant`）；有摘要；描述用富文本，上限 10 万字；相关商品可选 AI 推荐、自订或不显示。
- **价格**：原价、特价、零售价、成本价、会员价，以及按会员等级的分级价（`product_price_tier<id>`）；储位编号；商品货号；台湾营业税的商品税别；还支持定期购（周期 7–365 天，可设期数上限）。
- **数量**：可选无限数量、缺货时仍可接单；网店数量和实体店数量分开。
- **规格**：「皆同主商品价格」开关；有规格模板（给 POS 用）。
- **分类**：可多选，另设一个主分类；「精选商品」显示在首页。
- **SEO**：标题、简介、关键字、描述性 URL。
- **设定**：
  - 隐藏商品：不在店内展示，只能通过链接购买
  - 预购提示（双语）
  - 缺货提醒邮件（每天两次）
  - 单次购买数量限制
  - 定时上架
  - 销售时段
  - 不适用折扣
  - 所属供应商
- **商品设定（全店）**：前台的快速加入购物车、追踪清单、立即购买、价格区间、折扣比例、销量显示、按销量排序、登入前是否显示会员价。

## 3. Meta 接入（第三方服务 > Facebook）

- **基础设定（Facebook 商业增强套件，FBE）**：
  - 连接一个 Facebook 账号，再依次选企业管理平台（Business Manager）、主要粉丝专页、商品目录；
  - 新版 FBE 加入了线下转换 API。
- **广告行销**：广告账号；Pixel（数据集）；转换 API（已启用，可设规则）。
- **社群销售**：
  - 最多连接 10 个粉丝专页，本店连了 2 个：渠道仓-香港、大梦甄选女包；
  - 连接 Instagram 专业账号，可做 IG Direct 和 IG LIVE 同步；
  - 瞬时通知（One-Time Notification）：顾客点「通知我」后，可在一年内推送一则消息。
- **店铺**：Facebook 和 Instagram 商店（本店未启用）；Facebook 商务账号。
- **信使（Messenger）**：首次欢迎语、常用菜单（最多三层）、订单状态通知（顾客结账时选择订阅）。
- **网店应用**：
  - 顾客用 Facebook 登入网店，使用商家自己的 Facebook Developer 应用；
  - Messenger 快速注册链接（`/oauth/facebook/quick_sign_up`）。

## 4. 直播（SHOPLINE Live）与关键字

- **直播列表**：每天复制前一场（标题呈 `copy-(copy-(…))`）；显示每场成果（订单数、金额）。
- **其他功能入口**：「直播限定价」统一管理；打印留言标签；限制下单的黑名单（适用于 FB Page、IG、FB 社团）。
- **商品关键字库**：全店级，一个商品一个关键字（如 H9、A49），上限 10000 条；同样支持组合商品和分类。
- **通用设置 > 下单设置**：
  - 关键字规则三选一：包含；关键字+数量；精确匹配。
  - 直播时：顾客可随意下单，或必须手动生效关键字后才能下单。
  - 直播结束后：维持关键字状态，或全部失效。
  - **保留库存**：顾客加入购物车时锁定库存一段时间，到期自动释放，但不从购物车移除；开播后不可修改。
  - 库存不足提醒：卖光或低水位时提示主播。
  - 订单自动加直播标签：用于订单筛选；直播结束 60 天后自动关闭；全店最多 100 个标签。
- **信息设置**（消息模板，变量为 `{products}`、`{total}`、`{title}`）：
  - 欢迎留言
  - 商品推荐
  - **下单成功消息**：若顾客在 FB 7 天、IG 24 小时内未与 Page 互动，先发一条带按钮的**前置消息**，顾客点击后再发购物车明细和「前往填写收货地址」按钮。这是在 Meta 消息窗口规则下的合规做法。
  - 无库存消息
  - 结账提醒：顾客下单后迟迟不结账时提醒。
- **结帐设定**：可「锁定直播/贴文销售商品」，顾客不能在购物车里修改或删除这些商品的数量；可设结账必须登入；结账页会员和订阅勾选项的默认值。
- **贴文销售**：用 FB 贴文留言下单，另有抽奖、抢优惠等互动玩法（本店未使用）。
- **快速结帐网址**：选好商品生成一个预装购物车的链接，可套用分润活动。

## 5. 收款与物流（本店实况）

付款方式**全部是到付或取货付款**：
- 货到付款（Cash on Delivery）
- 全家、7-11 取货付款（C2C）
- 黑猫宅配货到付款
- 新竹物流货到付款
- 7-11 C2B 退货（不付款）

本店**没有开通线上刷卡**（另有 SHOPLINE Payments 入口）。

## 6. 与我们（R4，156b1ca）的对比

| 能力 | SHOPLINE | 我们 | 结论 |
|---|---|---|---|
| 一个店连接多个 FB Page | 最多 10 个；本店用了 2 个 | **每店 1 个**（`integration.meta_connections` 的主键是 `(tenant_id, store_id)`） | **试点差距**：商家要同时用渠道仓-香港和大梦甄选女包两个 Page |
| 宅配货到付款（黑猫、新竹） | 有，是本店的主要方式之一 | **无**（只有超商取货付款、银行转账、刷卡） | **试点差距** |
| 超商取货付款（7-11、全家 C2C） | 有 | 有（绿界；SANDBOX 未跑） | 对齐 |
| 关键字库、匹配模式、直播价、复制场次 | 有 | 有（全店级关键字库、EXACT 和 QTY 两种模式、0092 直播价、从关键字库或场次导入） | 基本对齐；我们没做「包含」匹配，是有意为之（防止误下单） |
| 首次私信、Meta 消息窗口 | 窗口外先发前置消息、顾客点按钮后再发链接 | 评论 private reply 只发一次，内含认领链接 | 对齐（机制不同，都合规） |
| 结账提醒、无库存回复、直播订单标签、打印留言标签、黑名单 | 有 | 无 | 后续单元 |
| 加购时保留库存 | 加购即锁库存 N 分钟 | 在结账 Begin 时才锁 | 策略不同；我们的做法在直播热卖时会出现「已认领、最后没货」 |
| 锁定直播商品不让改数量 | 商家可选 | 改数量后失去直播价，但能改 | 可加成店铺开关 |
| 商品：限购、定时上架、销售时段、隐藏商品（仅链接）、缺货仍可接单、会员价/分级价、成本价、多语言名称 | 有 | 有：草稿/上架、SEO、规格、划线价、分类、库存提示；无：限购、定时、隐藏链接、会员价 | 后续单元 |
| 消息工作台（统一收件箱） | 有 | 无（只有认领看板） | 后续单元 |
| Messenger 菜单、欢迎语、订单状态通知、FB 登入 | 有 | 无 | 后续单元 |
| 主题 | 十余套主题 + SHOP Builder | 一套主题 + 装修编辑器（0087） | 可接受 |
| 架构 | 核心后台 + 微前端 + OAuth 开放平台 | Go 模块化单体 + PG | 保持现架构 |
