## 审计与任务

审计时现有账簿以宽表格和下方操作托盘承担高频核对；主 CTA 不重复，网站客服/Meta/平台支持分域。入口当时尚不存在，不能照搬完整侧导航、商品表、渠道状态或 KPI 卡片墙：未开店者没有可操作店铺。实际入口只保留轻量身份/语言栏和必要步骤。

用户任务：经外部 OIDC 登录后，填写新商户名称、店铺名称、允许的币种、初始库存仓名称，再原子开通内部工作区。商户与仓库均为文本输入，不是选择已有组织或仓库。界面语言独立于币种。未登录状态在同一视觉框架内显示“通过身份服务登录”；不自建密码输入，也不把 Meta 绑定当商家登录。提供商未配置时必须显示未配置，不给假按钮。

物理场景：商家在白天办公室电脑上准备新店，需清楚核对名称和货币；浅冷灰工作面、海军蓝框架与青绿主操作沿用现有 UI。手机保持同样顺序并允许自由切换简体、繁体、英语。

## C 实施约束

三步：商户名称 → 店铺名称与交易币种 → 初始库存仓及最终只读核对。前两步只改变本地草稿；第三步使用既有 initial-store 四字段合同一次原子提交。提交结果未知时保留原请求体与幂等键，只重试该请求，不允许改字段或另建请求绕过。语言切换保留草稿和当前步；绝不存储登录 token。成功说明仅内部工作区创建，不承诺已发布、支付或物流可用。

## 已实现的状态与恢复边界

- 前两步仅校验和推进草稿；最后一步发送 `tenant_name`、`store_name`、`warehouse_name`、`currency` 四字段。提交中抑制重复调用，成功后主动作变为进入工作区。
- 草稿、当前步、待决请求保存在当前标签页的 `sessionStorage`，命名空间由当前 CSRF 会话边界的 SHA-256 摘要确定；不保存登录 token。恢复前校验格式、期限、名称与币种策略。写入或回读失败时禁止提交。
- 网络异常、不可解析响应、服务端错误或不完整成功响应会保留原序列化请求体与幂等键并锁定字段。恢复按钮重发同一请求；409 同时呈现先检查工作区状态的提示和入口。
- 401 清除旧会话草稿并重新登录；若另一账号替换 cookie，旧标签页在发送前发现会话边界变化，清除旧草稿并刷新，不发送旧账号的开通 POST。
- 成功只声明内部工作区已创建。店铺发布、支付、承运商接通不在本切片成功口径内。

## Direction contract 的持久位置

`apps/admin/app/[locale]/layout.tsx` 保存 `THESIS`、`OWN-WORLD`、`STORY`、`FIRST VIEWPORT`、`FORM`、`FINISH`，明确 C 三步向导、surface seed `57bb98dc` 与不变的账簿 seed `3046f272`。合同以 `data-commerce-design-contract="57bb98dc"` 的惰性 `<template>` 承载字面 HTML comment，是 `<body>` 的首个作者子元素，不影响布局或辅助技术。

这是 React/Next 对原始注释持久化的明确适配：运行时可在其前插入一个空且 hidden 的 Suspense DIV，不能称作字面上的首个 DOM 节点。已有针对性 gate 校验父节点为 body、允许的精确前缀以及 `template.content.firstChild` 为 `Node.COMMENT_NODE`。
